# 레퍼런스 읽는 법

[API 레퍼런스](../api-reference/wiki/README.md)는 서비스 코드의 OpenAPI에서 자동 생성한 문서다. 이 문서는 생성된 페이지의 각 표를 읽는 법(엔드포인트 표, 파라미터 표, 필수 열, 필드 표의 `[]`와 점 표기, curl 블록)과 문서가 코드에서 다시 만들어지는 절차를 설명한다.

## 구조

레퍼런스는 **서비스 → 리소스 → 엔드포인트** 세 단계다.

| 단계 | 페이지 | 내용 |
|---|---|---|
| 서비스 | `WIKI API` / `ALM API` / `Org API` (각 폴더의 개요) | 서비스 설명, 버전, 기본 URL, 엔드포인트 수, 인증 방법, 리소스 목록 |
| 리소스 | `Pages`, `Issues`, `Grants` 등 | 그 리소스의 엔드포인트 표 + 엔드포인트별 상세 |
| 엔드포인트 | 페이지 안의 `## GET /api/wiki/pages/{id}` 절 | 파라미터, 요청 본문, 응답, curl |

리소스는 서비스 코드의 컨트롤러 태그와 같다. 어떤 리소스에 있는지 모르는 엔드포인트는 서비스 개요의 리소스 표에서 설명을 보고 찾거나, 경로 문자열로 페이지 안을 검색한다.

## 페이지 머리

모든 생성 페이지는 아래 안내로 시작한다.

> 자동 생성 — 원본은 각 서비스의 컨트롤러 주석. 직접 고치지 말 것

문서에서 잘못된 설명을 발견하면 문서가 아니라 **서비스 코드의 주석**을 고쳐야 다음 생성 때 반영된다.

## 엔드포인트 표

리소스 페이지 첫머리의 표다. 한 줄이 엔드포인트 하나이고, 요약을 누르면 같은 페이지의 상세 절로 간다.

| 메서드 | 경로 | 요약 |
| --- | --- | --- |
| `PUT` | `/api/wiki/pages/{id}` | 페이지를 수정한다 — expectedVersion이 현재 버전과 다르면 409 |

- 경로의 `{id}`처럼 중괄호로 싼 부분은 경로 파라미터다.
- 요약의 대시(`—`) 뒤는 그 엔드포인트의 주의점이다. 409 조건, 기본값, 부작용이 여기에 적힌다.

## 파라미터 표

경로·쿼리 파라미터가 있는 엔드포인트에만 나온다.

| 이름 | 위치 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| `spaceId` | path | `integer(int64)` | 예 |  |
| `parentId` | query | `integer(int64)` |  | 부모 페이지 ID. 비우면 스페이스 루트 |

- **위치**: `path`는 경로에 치환, `query`는 `?이름=값`으로 붙인다.
- **필수**: "예"면 빠뜨릴 수 없다. 비어 있으면 생략 가능이고, 기본값은 설명에 적혀 있다.
- **타입**: `integer(int64)`는 숫자, `string(date)`는 `YYYY-MM-DD`, `string(date-time)`은 ISO-8601 UTC, `boolean`은 `true`/`false`, `string enum(a, b)`는 그 값 중 하나. `string[]`처럼 `[]`가 붙으면 같은 이름을 반복해 여러 개 보낸다. 형식 규칙은 [요청·응답 규약](./20-conventions.md)에 있다.

## 요청 본문

본문이 있는 엔드포인트는 `application/json — SchemaName (필수)`처럼 콘텐츠 타입과 스키마 이름을 적고, 그 아래 필드 표가 온다. 파일 업로드는 `multipart/form-data`이며 파트 이름은 `file`이다. 단, ALM 첨부와 Org 아바타 페이지는 생성기 한계로 `application/json — object`라고 표기돼 있는데 실제 요청은 multipart다([첨부 파일](./50-files.md)).

## 필드 표

요청 본문과 응답 본문 모두 같은 표 모양이다.

| 필드 | 타입 | 필수 | 설명 | 예시 |
| --- | --- | --- | --- | --- |
| `title` | `string` | 예 | 페이지 제목 | `배포 절차` |
| `labels` | `string[]` |  | 라벨 | `["regression","frontend"]` |
| `details` | `IssueDetailsRequest` |  | 상위 이슈·스프린트·마감일·라벨 등 세부 항목. 생략하면 기존 값을 보존한다 |  |
| `details.sprintId` | `integer(int64)` |  |  |  |
| `items` | `IssueResponse[]` |  |  |  |
| `items[].key` | `string` |  | 사람이 읽는 이슈 키 | `ALM-42` |

읽는 규칙:

- **필수 열**은 요청 본문에서만 의미가 있다. 응답 표에서는 비어 있어도 서버가 항상 채운다(값이 없으면 `null`).
- **타입이 스키마 이름**(`IssueDetailsRequest`)이면 중첩 객체다. 바로 아래에 `details.sprintId`처럼 **점(`.`)으로 이어진 줄**이 그 객체의 필드다.
- **`[]`가 붙은 타입**(`string[]`, `IssueResponse[]`)은 배열이다. 배열 요소가 객체면 `items[].key`처럼 **`[]` 뒤에 점**으로 요소의 필드를 적는다.
- **`string enum(a, b, c)`**는 허용 값 목록이다. 대소문자를 그대로 쓴다.
- **예시 열**은 JSON 값이 아니라 표시용 문자열이다. 문자열 예시에는 따옴표가 없고, 배열·객체 예시는 JSON으로 적혀 있다.

위 표를 JSON으로 옮기면 이렇다.

```json
{
  "title": "배포 절차",
  "labels": ["regression", "frontend"],
  "details": { "sprintId": 12 },
  "items": [{ "key": "ALM-42" }]
}
```

## 응답 표

| 상태 | 설명 | 스키마 |
| --- | --- | --- |
| `200` | OK | `PageResponse` |
| `400` | 요청 검증 실패 | `PlatformError` |
| `409` | 버전 충돌 — expectedVersion 불일치 | `PlatformError` |

- 성공 코드는 하나다(`200` · `201` · `204`). `204`는 본문이 없다.
- 오류 코드의 스키마는 항상 `PlatformError`(`{"error": "메시지"}`)다. 설명 열이 그 엔드포인트에서 그 코드가 나는 **이유**다. 대응 방법은 [오류 처리](./30-errors.md).
- 성공 응답의 본문은 표 아래 `**200 본문** — PageResponse` 제목의 필드 표로 이어진다. 바이너리 응답(PDF·첨부)은 필드 표 대신 설명만 있다.

## curl 블록

각 엔드포인트 끝의 curl은 필수 파라미터와 필수 필드만 채운 최소 호출이다.

```bash
curl -X PUT "https://<your-host>/api/wiki/pages/<id>" \
  -H "Authorization: Bearer chanho_pat_…" \
  -H "Content-Type: application/json" \
  -d '{ "content": "…", "expectedVersion": 3, "title": "…" }'
```

- `<your-host>`와 `<id>` 같은 꺾쇠 자리는 실제 값으로 바꾼다.
- 본문의 값은 필드 표의 예시 열에서 가져온 것이라 그대로 보내면 안 되는 경우가 있다(`expectedVersion`은 방금 읽은 값이어야 한다).
- 선택 필드는 빠져 있다. 필요한 것을 필드 표에서 골라 추가한다.

## 문서가 만들어지는 절차

레퍼런스는 손으로 쓰지 않는다. 세 단계가 모두 멱등이라 코드가 바뀌면 같은 순서로 다시 돌린다.

| 단계 | 하는 일 | 원본 |
|---|---|---|
| 1. 수집 | 각 서비스가 띄운 OpenAPI(`/v3/api-docs`)를 받아 저장 | 서비스 컨트롤러의 주석과 스키마 애너테이션 |
| 2. 생성 | 저장된 OpenAPI를 서비스 폴더 + 리소스별 마크다운으로 변환 | 1단계 결과 |
| 3. 동기화 | 생성된 마크다운을 공개 문서 위키의 "API 레퍼런스" 폴더로 올림 | 2단계 결과 |

그래서 다음이 성립한다.

- **문서 = 배포된 코드.** 레퍼런스에 있는 엔드포인트는 실제로 존재하고, 없는 엔드포인트는 없다. 이 가이드가 레퍼런스와 다르면 레퍼런스가 맞다.
- **설명이 빈 필드**는 코드에 주석이 아직 없는 것이다. 타입과 필수 여부는 그래도 정확하다.
- **페이지 머리의 버전**(예: `0.0.1-SNAPSHOT`)은 서비스 빌드 버전이다. 문서가 언제 코드에서 만들어졌는지는 위키 페이지의 수정 시각으로 본다.
